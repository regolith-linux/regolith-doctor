# PKG-004: A feature has no provider: its package was removed and nothing replaces it

| | |
|---|---|
| Area | PKG |
| Sessions | i3 (X11) and sway (Wayland) |
| Releases | Regolith 3.4, 3.5 |
| Needs | files only |
| Fix class | guided |
| Status | planned |

## What it detects

Removing a Regolith package and adding your own partial is the documented way to replace it, so a missing package is fine on its own. It is a problem when nothing provides the feature any more: no `bar {}` block, no binding that starts a launcher or terminal, no lid handling on a laptop while regolith-powerd holds logind's lid switch, no notification daemon, no compositor on X11, no polkit agent, no `i3-wm` for the X11 session (login loop), or no look. Features expected from a package split that was never installed (control-center bindings, the clock block) also count.

## How it is detected

The doctor looks at roles, not package names. A table shipped with the doctor lists each role (bar, launcher, terminal binding, lid switch, notifications, compositor, polkit agent, look, session window manager), how to see it in the effective configuration, resources or installed files, and which package normally provides it. Roles without a provider are reported; missing `Recommends:` from `/var/lib/dpkg/status` are reported only as information.

## Fix

The doctor names the package that usually fills the role or shows how to provide it at user level. Guided: you choose and confirm.
