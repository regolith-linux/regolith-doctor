# PWR-001: Lid switch overwritten by a user binding, or handled by nothing that suspends

| | |
|---|---|
| Area | PWR |
| Sessions | sway (Wayland) |
| Releases | Regolith 3.4, 3.5 |
| Needs | files only |
| Fix class | guided |
| Status | planned |

## What it detects

Two cases. First, a user `bindswitch lid:on` replaces the one from the `96_clamshell` partial while regolith-sway-clamshell is installed: sway shows a swaynag warning and Regolith's clamshell handling stops. Second, whatever packages are installed, the effective lid binding never suspends (for example it only runs `output eDP-1 disable`) while regolith-powerd holds the logind lid inhibitor, so closing the lid on battery with nothing docked leaves the laptop awake and unlocked. The second case may be intended, so it is a warning that shows the evidence; a hard-coded `eDP-1` is noted.

## How it is detected

The doctor reads the installed package set (is regolith-sway-clamshell installed and its partial present, is regolith-powerd installed), builds the effective include list and parses the `bindswitch` lines. Only partials whose package is installed count. With a running session, `systemd-inhibit --list` confirms the powerd inhibitor.

## Fix

First case: disable the user partial, or remove the clamshell package as the documentation describes. Both cases: the doctor points to the `wm.clamshell.*` and `wm.lidclose.action.*` resources. Guided: changes are shown and applied only after you confirm.
