# CFG-003: Config from an older Regolith major is still around and ignored

| | |
|---|---|
| Area | CFG |
| Sessions | i3 (X11) and sway (Wayland) |
| Releases | Regolith 3.4, 3.5 |
| Needs | files only |
| Fix class | guided |
| Status | planned |

## What it detects

Configuration left from Regolith 1.x or 2.x, such as `~/.config/regolith2`, `~/.config/regolith`, `~/.Xresources-regolith`, or `kanshi` and `picom` folders under `regolith2`. Regolith 3 never reads these, so the user's settings quietly disappear after the upgrade.

## How it is detected

Looks for those paths in HOME, notes when `~/.config/regolith3` is missing or almost empty, and lists keys inside the old files that have a 3.x name (using the XRES-002 rename table).

## Fix

Shows a migration preview: which files would move where and which keys would be renamed, then applies it on request with backups. Guided: applied only after confirmation.
