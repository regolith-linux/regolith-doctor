# ENV-001: Platform Regolith does not support

| | |
|---|---|
| Area | ENV |
| Sessions | i3 (X11) and sway (Wayland) |
| Releases | Regolith 3.4, 3.5 |
| Needs | files only |
| Fix class | report-only |
| Status | implemented |

## What it detects

The machine is not one Regolith publishes packages for, so problems are expected that no Regolith change can fix. Three cases are reported today:

- The distribution is neither Ubuntu nor Debian, nor derived from one of them (error). Derivatives such as Linux Mint or Pop!_OS are left to APT-007.
- The system runs under Windows Subsystem for Linux, where the desktop session, display server and input stack are not the ones Regolith expects (warning).
- The CPU architecture has no Regolith packages; the archive builds amd64 and arm64 only (error).

If no `os-release` file exists at all, the doctor cannot tell what the system is and says so (info).

## How it is detected

- `/etc/os-release`, falling back to `/usr/lib/os-release`: `ID` and the `ID_LIKE` list are compared with the distributions in `data/platforms.toml`.
- `/proc/version` and `/proc/sys/kernel/osrelease`: a kernel built by Microsoft for WSL has `microsoft` in its version string.
- `/proc/sys/kernel/arch`: the kernel's machine name (`x86_64`, `aarch64`, ...) is mapped to a Debian architecture with the same table. A missing file is not a finding.

Remote sessions (xrdp, VNC, SPICE), need the running session's environment and will come with the live probes.

## Fix

None: the doctor explains why the platform is a problem and what is supported. Report-only: nothing is changed.
