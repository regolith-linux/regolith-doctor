# APT-010: Leftover insecure apt overrides for the Regolith host

| | |
|---|---|
| Area | APT |
| Sessions | i3 (X11) and sway (Wayland) |
| Releases | Regolith 3.4, 3.5 |
| Needs | files only |
| Fix class | guided |
| Status | planned |

## What it detects

Workarounds shared during past certificate outages are still in place: `Acquire::https::<regolith host>::Verify-Peer "false"` (or `Verify-Host`), or `[trusted=yes]` or `allow-insecure=yes` on a Regolith entry. apt then accepts unverified data from that host.

## How it is detected

The doctor scans `/etc/apt/apt.conf` and `/etc/apt/apt.conf.d/*` for `Verify-Peer` or `Verify-Host` set to false, either scoped to a Regolith host or global, and checks Regolith entries for the `trusted=yes`, `allow-insecure` and `allow-weak` options.

## Fix

The doctor removes the override after a backup. Guided: you confirm first.
