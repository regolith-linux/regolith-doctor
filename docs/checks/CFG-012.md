# CFG-012: Session parity: a change made for one session only

| | |
|---|---|
| Area | CFG |
| Sessions | i3 (X11) and sway (Wayland) |
| Releases | Regolith 3.4, 3.5 |
| Needs | files only |
| Fix class | guided |
| Status | planned |

## What it detects

A change that reaches only one of the two sessions: a user partial that re-declares `set_from_resource $var key <other default>` where one Xresources line would serve both; a partial with nothing sway-specific kept in `sway/config.d` instead of `common-wm/config.d`; or effective bindings such as `$mod+Return` that differ between i3 and sway. A common package removed and replaced only under `sway/config.d`, for example, leaves the i3 session without a terminal binding.

## How it is detected

Compares user re-declarations with the `set_from_resource` defaults of shipped partials that are installed (package in dpkg status, file on disk); classifies user partials by session-only commands (`input`, `output`, `bindswitch`, `swaymsg`, `app_id`); and compares the effective binding sets of the two sessions.

## Fix

Offers the Xresources line and the move of the partial to `common-wm/config.d`. Guided: applied only after confirmation.
