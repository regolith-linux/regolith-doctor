# APT-003: Signing key missing, expired or configured the deprecated way

| | |
|---|---|
| Area | APT |
| Sessions | i3 (X11) and sway (Wayland) |
| Releases | Regolith 3.4, 3.5 |
| Needs | files only |
| Fix class | guided |
| Status | planned |

## What it detects

The Regolith entry cannot be verified: its `signed-by` option points at a file that is not there, the key in that file has expired (for example the 2023 key) or is not the archive's key, or the key only exists in the old apt-key locations. apt reports `NO_PUBKEY` or that the repository is not signed.

## How it is detected

The doctor resolves the `signed-by=` option or deb822 `Signed-By:` field, which can be a path or an inline armoured key. It checks that the file exists and is readable, reads the key's fingerprint and expiry from the OpenPGP packets, and compares the fingerprint with the Regolith fingerprints in a table shipped with the doctor. It also looks for Regolith keys in `/etc/apt/trusted.gpg` and `/etc/apt/trusted.gpg.d/`.

## Fix

The doctor installs the current keyring, bundled with it rather than downloaded, as `/usr/share/keyrings/regolith-archive-keyring.gpg` and points the entry at it. Guided: shown first, applied after you confirm.
