# APT-001: Regolith apt source uses the wrong codename

| | |
|---|---|
| Area | APT |
| Sessions | i3 (X11) and sway (Wayland) |
| Releases | Regolith 3.4, 3.5 |
| Needs | files only |
| Fix class | guided (can be applied without asking as root with `--yes`: one reversible file edit) |
| Status | planned |

## What it detects

A Regolith apt entry names a suite that is not the codename of the running system. Typical causes are a typo copied from release notes (`manic` instead of `mantic`) or an entry left on the old codename after a distribution upgrade. apt then fails to fetch the Regolith index or offers no Regolith packages.

## How it is detected

The doctor parses every entry in `/etc/apt/sources.list`, the one-line `*.list` files and the deb822 `*.sources` files under `/etc/apt/sources.list.d/`. An entry counts as Regolith when its host is `archive.regolith-desktop.com` or a known former Regolith host. Its suite is compared with `VERSION_CODENAME` in `/etc/os-release` (or the base codename on a derivative, see APT-007) and with the codenames listed in a table shipped with the doctor.

## Fix

The doctor rewrites the suite of that one entry, keeping comments, options and layout, backs up the file and tells you to run `apt update`. Guided: the change is shown and applied only after you confirm.
