# KBD-002: Bindings use keys the active keyboard layout does not have

| | |
|---|---|
| Area | KBD |
| Sessions | i3 (X11) and sway (Wayland) |
| Releases | Regolith 3.4, 3.5 |
| Needs | files only |
| Fix class | report-only |
| Status | planned |

## What it detects

On layouts such as AZERTY, Swiss, Czech, Lithuanian, Neo or Dvorak, some default bindings cannot be typed: the number-row workspace keys and several symbol keys are unreachable. Some keys also collide, for example `6` on the French layout produces `minus`, which the gaps partial already binds.

## How it is detected

The doctor finds the active layouts (GSettings input sources, sway `xkb_layout`) and reads the keysyms of each key from the XKB symbols files under `/usr/share/X11/xkb/symbols`. It reports bindings whose keysym is on no key of the first layout, and keysyms that end up on the same key.

## Fix

The doctor explains the problem and suggests `bindcode`, or the key-position option proposed in https://github.com/regolith-linux/regolith-wm-config/pull/137 once it is released. Report-only: nothing is changed.
