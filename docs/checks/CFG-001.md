# CFG-001: User partial binds a key the shipped config already binds

| | |
|---|---|
| Area | CFG |
| Sessions | i3 (X11) and sway (Wayland) |
| Releases | Regolith 3.4, 3.5 |
| Needs | files only |
| Fix class | guided |
| Status | planned |

## What it detects

A key combination, in the same mode, is bound both by a user partial and by a shipped partial that is actually present. i3 reports a duplicate binding and shows i3-nagbar at every login; sway lets the later binding win and queues a swaynag warning unless the user binding carries `--no-warn`.

## How it is detected

The doctor first works out which shipped partials are present: installed packages from `/var/lib/dpkg/status`, the files each one owns from `/var/lib/dpkg/info/<pkg>.list`, checked against the disk. Files under `/usr/share/regolith` that no installed package owns are labelled as such. It then builds the effective include list the way the root config does (see CFG-002), expands `set` and `set_from_resource` variables with the effective resources, normalises every `bindsym` and `bindcode` (modifiers, keysym case and aliases, flags, mode) and reports each collision with both file:line locations and the owning package. A user partial that takes over the bindings of a partial whose package was removed is the documented way to replace it and is not a finding.

## Fix

Offers to disable the user partial (rename to `<name>.disabled`) or the one line, to add `--no-warn` for an intended sway override, or to use the Xresources key the shipped partial reads for launcher keys. Guided: the change is shown and applied only after confirmation.
