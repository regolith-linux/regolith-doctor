# CFG-002: User partial with a shipped partial's name: adds or replaces

| | |
|---|---|
| Area | CFG |
| Sessions | i3 (X11) and sway (Wayland) |
| Releases | Regolith 3.4, 3.5 (additive); later regolith-wm-config (replacement) |
| Needs | files only |
| Fix class | guided |
| Status | planned |

## What it detects

A user partial named like a shipped one. In released 3.4 and 3.5 the user file is loaded in addition to the shipped file, while most users expect it to replace it. With https://github.com/regolith-linux/regolith-wm-config/pull/133 merged the user file does replace the shipped one, and an empty file or a link to `/dev/null` turns the partial off.

## How it is detected

The loading mode comes from the effective root config, not from a version number: four `include .../config.d/*` lines mean additive loading (a file is skipped only when its real path was already included); `include $(/usr/bin/regolith-wm-partials i3|sway)` means the replacement rules of that pull request. Only partials whose package is installed and whose file is on disk count; a same-name user file whose shipped twin was removed with its package is the documented replacement and is not a finding. For each match the doctor reports what happens under the active mode and which variables the shipped file set that the user copy no longer sets.

## Fix

Under the additive mode it shows the documented route (copy the partial and remove the package, or use an Xresources key) and offers to disable the user file. Under the replacement mode it only explains. Guided: nothing changes without confirmation.
