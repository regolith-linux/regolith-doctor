# KBD-001: A GNOME or XKB shortcut grabs a Regolith key

| | |
|---|---|
| Area | KBD |
| Sessions | i3 (X11) mostly, through gnome-flashback; sway (Wayland) for XKB options |
| Releases | Regolith 3.4, 3.5 |
| Needs | files only |
| Fix class | guided |
| Status | planned |

## What it detects

A GNOME shortcut or an XKB option takes a key combination that Regolith also binds, so the Regolith binding never fires. Typical cases: Super+L taken by the screensaver, Print by the screenshot tool, and Super+Space by input-source switching or the `grp:win_space_toggle` option.

## How it is detected

The doctor reads the effective GSettings values for `org.gnome.settings-daemon.plugins.media-keys`, `org.gnome.desktop.wm.keybindings` and the `xkb-options` of `org.gnome.desktop.input-sources`, parses the accelerators, and intersects them with the effective window manager bindings.

## Fix

The doctor offers to reset or clear the GSettings key that collides, keeping the old value so the change can be undone. Guided: the change is shown and applied only after you confirm.
